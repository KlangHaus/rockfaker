# AGENTS.md

Guidance for AI coding assistants working in **rockfaker** — KlangHaus' centralized
test-data repo: seeded faker library, committed JSON fixtures, and Mockoon HTTP stubs.

## Repo role

| Layer | Path | Purpose |
| --- | --- | --- |
| Library | `src/` | Zero-dep runtime faker — import in tests and generators |
| Fixtures | `fixtures/` | Committed JSON — single source for Mockoon + direct imports |
| HTTP mocks | `mockoon/` | Mockoon environments serving `fixtures/` (auth, Studio CDN, Etude, etc.) |

Consumers: **Etude**, **expo-starter**, local Tilt stacks, CI integration tests.

## Non-negotiable: musical references in all data

**Every piece of fake data in this repo must carry a musical reference.** This is the
product identity of rockfaker — not optional decoration.

Musical reference means at least one of:

- Real or plausible **musician / band names** (weighted like existing locales)
- **Genres**, **albums**, **song titles**, **tour / venue** vocabulary
- **Wordplay** that a music fan recognizes (e.g. course titles that nod to songs or artists)
- Danish locale: Danish/Nordic music culture is fair game (Gasolin', MØ, Lars Ulrich, etc.)
- English locale: rock, punk, metal, grunge canon (Hendrix, Nirvana, Lemmy, etc.)

### Applies to

- New **locale strings** in `src/locales/{da,en}/`
- New **modules** under `src/modules/`
- **Fixture generators** in `scripts/generate-fixtures.ts`
- **Mockoon inline bodies** (notification ids, error messages, stub labels)
- **Education / Etude demo data** — academic labels are fine only if they also include a
  musical nod (song quote, album pun, artist name in instructor field, etc.)

### Does not apply to

- Pure infrastructure keys (`tenant_id`, `pk_live_*`, JWKS stub `kid`, HTTP status codes)
- Structural JSON shape fields (`id`, `slug`, `version`, ISO timestamps)

When adding non-music domain modules (e.g. finance, CRM), **still** embed musical flavor
in display strings — use `person` / `band` modules or explicit music-themed copy.

## Commands

```bash
bun install
bun test
bun run build
bun run fixtures:gen      # regenerate fixtures/ from seed 42
bun run fixtures:check    # CI — fail if fixtures drift
bun run mock:etude        # Mockoon on http://localhost:4010
bun run mock:up           # fixtures:gen + mock:etude
bun run mock:stop
bun run playground        # interactive REPL
```

## Adding data (workflow)

1. Extend locale data and/or `src/modules/` — keep **seeded** PRNG via `Engine`.
2. Run `bun test` — add tests for stable seed output.
3. Update `scripts/generate-fixtures.ts` if fixtures should reflect new shapes.
4. Run `bun run fixtures:gen` and commit `fixtures/` changes.
5. Point Mockoon routes at fixture files (`bodyType: FILE`) — avoid duplicating large
   JSON inline in `mockoon/*.json`.
6. Document new endpoints in `mockoon/README.md`.

## Architecture rules

- **Published library stays zero runtime dependencies.** `@mockoon/cli` is dev-only.
- **`COURSE_COUNT` and default seed (`42`)** live in `scripts/generate-fixtures.ts`; document
  changes in `fixtures/manifest.json`.
- Prefer **FILE-backed** Mockoon responses over INLINE for anything generated by rockfaker.
- Use `===` / `!==` in TypeScript; comments in English; commit messages in English.

## Mockoon environments

| File | Port | Scope |
| --- | --- | --- |
| `mockoon/etude.json` | 4010 | Etude deps: Studio tokens, bootstrap, JWKS, notifications, permissions |

Add new environments as `mockoon/<consumer>.json` — do not overload etude.json with
unrelated product mocks unless shared across KlangHaus dev stacks.

## Before opening a PR

- [ ] All new display strings have musical references (review against rule above)
- [ ] `bun test` green
- [ ] `bun run fixtures:check` green if locales/generator touched
- [ ] `mockoon/README.md` updated if routes changed
- [ ] No secrets or real API keys in fixtures (use `pk_live_*` / stub JWKS only)
